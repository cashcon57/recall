# Recall v2.2 Trustworthy Memory + Hermes Integration Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Ship Recall v2.2 as a source-aware, lifecycle-managed MCP memory server with optional self-update support and a clear Hermes integration model for cross-repo / Discord-channel-specific project work.

**Architecture:** Keep Recall focused on curated durable memory. Add provenance, status, confidence, verification, and supersession directly to the `memories` row so retrieval can avoid stale-memory rot. Keep raw project corpus/RAG ingestion out of v2.2; only scope it for v2.3. Add optional updater tooling as local/GitHub-run deploy automation that preserves user-owned config.

**Tech Stack:** TypeScript, Cloudflare Workers, D1, Vectorize, Workers AI, local SQLite/sqlite-vec backend, Docker/Postgres/pgvector backend, MCP Streamable HTTP, Hermes native MCP client.

## Data model

### New memory fields

Add to `memories` across all backends:

```sql
source_type TEXT NOT NULL DEFAULT 'manual',
source_url TEXT,
source_path TEXT,
source_line_start INTEGER,
source_line_end INTEGER,
source_title TEXT,
source_hash TEXT,
status TEXT NOT NULL DEFAULT 'active',
confidence REAL NOT NULL DEFAULT 0.75,
verified_at TEXT,
expires_at TEXT,
supersedes_key TEXT,
superseded_by_key TEXT
```

Allowed values:

```ts
export type MemorySourceType =
  | 'manual'
  | 'chat'
  | 'doc'
  | 'code'
  | 'issue'
  | 'pull_request'
  | 'log'
  | 'web'
  | 'inferred';

export type MemoryStatus = 'active' | 'stale' | 'superseded' | 'deprecated';
```

Retrieval defaults:

```ts
include_statuses = ['active', 'stale'];
include_provenance = true;
format = 'text';
```

Rules:

- `active`: normal retrieval.
- `stale`: retrieved by default with warning and slight score penalty.
- `superseded`: excluded by default; available via `include_statuses`.
- `deprecated`: excluded by default; available via `include_statuses` for audits.

### Task 8: Implement `supersedes` handling inside `store_memory`

**Objective:** Allow one-call replacement of stale memories.

**Files:**
- Modify: `src/tools.ts`
- Test: `test/supersession.test.ts`

**Behavior:**

If `store_memory` receives `supersedes: oldKey`:

1. Validate `oldKey` exists unless caller passes an overwrite of same key.
2. Store new row as `status = active`.
3. Set new row `supersedes_key = oldKey`.
4. Mark old row:
   - `status = 'superseded'`
   - `superseded_by_key = newKey`
   - `updated_at = now`
5. Add memory relationship edges:
   - `newKey -> oldKey`, type `supersedes`, strength `1.0`
   - `oldKey -> newKey`, type `superseded_by`, strength `1.0`

**Acceptance:**

- old memory excluded from default retrieval.
- new memory retrieved and says it supersedes old.
- explicit `include_statuses: ['superseded']` can retrieve old and warns it was superseded.

Score penalty:


Do not apply status filtering in Vectorize; D1 is canonical.

**Acceptance:**

- `stale` appears with warning.
- `superseded` excluded by default.
- `deprecated` excluded by default.

### Task 26: Add Hermes memory routing convention

**Objective:** Make cross-repo Recall useful without polluting global memory.

**Files:**
- Modify: `docs/HERMES_INTEGRATION.md`

**Routing rules:**

When storing from Hermes:

1. Determine project namespace from current workdir/repo if present.
2. If no repo, determine namespace from Discord channel/thread topic if known.
3. If neither is obvious, use `global` only for stable cross-project facts.
4. Include `source_type: chat` for Discord-derived memories.
5. Include `source_title` with server/channel/thread labels.
6. Use `status: active`, `confidence: 0.75` for user-stated facts; `confidence <= 0.6` for inferred facts.
7. Use `supersede_memory` rather than deleting stale guidance.

Example key format:

```text
<namespace>-<short-topic>-<kind>
```

Examples:


## Design constraints

- Keep old clients working.
- All schema migrations additive and forward-compatible.
- D1 remains canonical; Vectorize can have stale/orphan rows without corrupting answers.
- Retrieval must never trust vector metadata over DB row status.
- No secrets in memories.
- No API keys in Hermes `config.yaml` if wrapper-file pattern is available.
- No full source/corpus ingestion in v2.2.
- Auto-update is opt-in only.
